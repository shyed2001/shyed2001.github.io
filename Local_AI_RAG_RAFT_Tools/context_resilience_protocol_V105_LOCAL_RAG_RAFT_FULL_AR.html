نسخة عربية كاملة ذات بنية مماثلة للنسخة الإنجليزية.

الملخص التنفيذي

المحادثة الطويلة مؤقتة، أما حالة المشروع فيجب أن تكون دائمة. Markdown للحالة البشرية، JSONL للأدلة الآلية، YAML للتوجيه، Graphify/GraphRAG للرسوم، وGit للتدقيق.

١. المقدمة

عندما يكبر السياق تزداد التكلفة والكمون وصعوبة الاسترجاع وضغط واجهة المتصفح. الحل هو نقل الحالة المضغوطة لا نقل transcript كامل.

٢. السقف التقني

انتباه Transformer ينتج تفاعلات زوجية، لكن الكلفة العملية تتأثر أيضاً بذاكرة KV والتجميع والعتاد والأنوية والكمّ وخدمة المزود.

\[\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V\]

٣. آليات الترميز

حساب الرموز يختلف حسب النموذج: OpenAI وClaude وLlama والأنظمة المحلية ليست متطابقة.

٤. صيغ التسلسل

Markdown للتسليم البشري، YAML للإعدادات، JSONL للسجلات والأدلة، JSON للتبادل الصارم، وTOON خيار ناشئ للبيانات المتكررة.

٥. ضغط السياق

الضغط يحفظ الحقائق والقرارات والأدلة والمسارات الفاشلة ويحذف الحشو والتكرار.

٦. خطوط الإدخال الآلية

يمكن إدخال ملفات التسليم في Vector RAG وGraphRAG وGraphify وMemPalace والفهارس المحلية.

٧. الضغط الرمزي والتمهيد المتناثر

التمهيد المتناثر يساعد في استعادة السياق، لكنه لا يستبدل الأدلة الرسمية.

٨. آلة الحالة المستمرة

PROJECT-SPEC للقواعد الثابتة، SESSION-HANDOVER للحالة الحالية، FAILED-PATHS للذاكرة السلبية، DECISIONS للقرارات، EVIDENCE-LOG للأدلة.

٩. امتداد بنية CCGSC

يعمل CCGSC في Local RAG RAFT كنسيج تنفيذ ومزامنة بين Edge وDew وCluster وGrid وCloud control.

فقرة CCGSC: يُستخدم CCGSC كمعمارية خاصة بالمشروع لتنسيق عمل الذكاء الاصطناعي الموزع. في Local RAG RAFT يعمل كنسيج تنفيذ ومزامنة؛ Local RAG يسترجع الأدلة، RAFT يحسن التكيف مع المجال، Graphify/GraphRAG يكشفان العلاقات، وMarkdown/JSONL/YAML تحفظ الحالة والسياسة والأدلة.

١٠. مصفوفة القرار

مصفوفة القرار تلخص متى يستخدم كل تنسيق أو أداة.

١١. دليل التنفيذ

في المحادثة القديمة استخدم Prompt A للاستخراج؛ في الجديدة استخدم Prompt B للإدخال.

Role: You are a project-state extraction engine.
Task: Compress this conversation into durable project state.
Output: PROJECT-SPEC.md, SESSION-HANDOVER.md, FAILED-PATHS.md, DECISIONS.md, EVIDENCE-LOG.md.

١٢. قوالب قابلة للتشغيل

قوالب PROJECT-SPEC.md وSESSION-HANDOVER.md قابلة للاستخدام مباشرة.

١٣. تفريغ مخرجات الأدوات

لا تلصق مخرجات الأدوات الكبيرة؛ خزّنها خارجياً وضع مؤشراً وملخصاً.

١٤. أنماط سير العمل

المكتب: قرارات؛ الأكاديمية: claim/source؛ التطوير: Graphify-first؛ DevOps: incidents وأدلة وأسرار آمنة.

١٥. مصداقية الأدوات وسياسة القياس

يجب فصل الصيغ المستقرة عن الأدوات الناشئة؛ لا ادعاءات حادة دون benchmark.

١٦. مثال عملي

يمكن ضغط جلسة تصحيح ضخمة إلى هدف وقيود وقرارات ومسارات فاشلة وحالة وخطوة تالية.

١٧. متى لا يكون ضرورياً

المحادثات القصيرة لا تحتاج protocol كاملاً؛ يكفي الهدف والقرار والخطوة التالية والخطر.

١٨. الخاتمة

النتيجة: الانتقال من محادثة عابرة إلى إدارة حالة نشطة.

١٩. المراجع

المراجع تشمل Transformer وFlashAttention وRAG وRAFT وGraphRAG وGit وOWASP وJSONL وYAML وGraphify.

٢٠. قراءات إضافية

قراءات إضافية حول context engineering وcompression وGraphRAG وMarkdown.

٢١. منهجية القياس

أي benchmark يحتاج النموذج وtokenizer وdataset وbaseline وmetric وrepetitions وloss check وreproducibility.

٢٢. قائمة فحص الهجرة

قائمة الهجرة: objective، facts، decisions، failed paths، evidence، redaction، core files، Prompt B.
